# 动态照片播放恢复记录（2026-10-29）

## 历史依据

对比时 HEAD 为 9bf7860，HEAD~3 为 7da315f（2026-10-20 11:50:30 +08:00）。这两个提交中的动态照片处理器、瀑布流卡片、全局查看器和相册查看器相同。当前工作区另有把 Blob 播放改成接口 URL 直连的修改。

7da315f 的核心流程是：完整 fetch 视频字节 → video/mp4 Blob → 为播放器创建 Blob URL → video 播放。历史函数 convertMovToMp4 只是封装 Blob 类型，没有把 HEVC/H.265 转成 H.264。

## 当前实现

三个播放入口都使用同一个下载器和播放器资源管理函数：

- 瀑布流：静图加载后，在可见、非省流网络下低优先级预取；悬停和长按可主动请求。移开鼠标或结束触摸后，迟到的下载结果不会自动播放。
- 全局大图与相册：当前照片纹理准备好后可后台预取，主动播放时优先加载。切换照片或关闭查看器会使旧请求的 UI 结果失效。
- video 的 src 使用本地 Blob URL。请求 play() 时保留静图，playing 事件或播放成功后才显示视频层；下载或解码失败时保留静图，并在实况标记的提示中给出错误。

下载器保留同源 Cookie、请求重新验证权限。相同照片和视频地址共用进行中的下载。最多两个下载同时运行，其中后台下载最多一个；后台排队时已不可见的照片会被跳过。下载总超时覆盖响应体，默认 90 秒。下载缓存最多 12 项、64 MiB，过期时间 5 分钟；单个视频最大 64 MiB。各播放器独立持有和释放 Blob URL。

退出登录或切换账号时，清理动态视频缓存、取消旧请求并释放已挂载的播放器 URL。错误响应、空文件和长度不完整的响应不进入视频缓存，失败后允许重新尝试。

现有的图标配置和后端 Range 修改保持原样。数据库、Compose、镜像及运行中的容器未在本轮修改。
