# 2026-10-29 权限复核与提交说明

本轮针对本地扫描库、本地上传存储、相册、人物、地图、音乐与登录会话进行复核。只修改源码和测试；不运行镜像构建、不重启服务，不修改现有数据库文件、数据库结构、初始化地名数据或 Compose 配置。

## 已修复的问题

| 问题 | 处理方式 |
| --- | --- |
| 中文目录的解锁 Cookie 名通过字符替换生成，不同目录可产生相同作用域 | 使用规范目录完整路径的 SHA-256 生成 Cookie 名；根目录原有作用域保持兼容。 |
| 页面、媒体与 BGM 分别判断祖先解锁，父目录令牌能越过子目录独立密码 | 共用继承检查；令牌必须对应当前生效密码。照片 SQL 还限制解锁范围位于当前密码来源目录之下。 |
| 路径在前端、查询解析器、相册服务中重复编解码，容易导致中文、空格、字面量百分号定位不同 | 前端把解码后的目录交给 query 序列化器；服务层保留字面量 `%`、规范分隔符，拒绝点目录与控制字符；媒体路径仅在 HTTP 边界解码一次。 |
| 相册详情、列表、嵌套节点的封面、计数、子节点和 BGM 过滤规则不一致 | 使用共享的扫描节点序列化函数递归过滤；封面及计数取自实际可见照片；锁定节点不返回封面、照片数、子节点或音乐。 |
| 扫描子相册 BGM 仅检查自身可见级别，遗漏祖先限制 | BGM 检查目录链生效可见级别，并使用同一密码继承规则。禁用扫描库的别名解析也返回 404。 |
| 普通用户被默认管理员规则拦在框架内置会话接口之外；旧会话或旧 `is_admin` 标志可能保留权限显示 | 精确放行自身会话的 GET/DELETE；用户与权限来自数据库 `role`；会话读取 hook 更新身份，删除账号不再返回旧身份。 |
| 公开设置仅依据 `is_public`，未二次排除机密字段 | 查询同时要求 `is_secret=false`，并拒绝已知私密设置键。 |
| GitHub OAuth 登录未进入已启用的本地 TOTP 流程 | 和密码登录共用短期挑战；验证前不签发正式会话，验证后原子消费挑战。 |
| 浏览器可在一个小时内直接复用媒体缓存，权限收紧后不必重新鉴权 | 媒体采用 private/no-cache；所有条件请求先鉴权，成功后才允许 304；API 响应 private/no-store。原图及转换缩略图有 ETag，可复用已缓存字节。 |
| SSR 的部分相册/人物请求没有转发用户 Cookie；数据缓存只按角色或 URL 区分 | 采用 useRequestFetch；缓存键包含账号身份。画廊退出/切换身份时立即清理元数据、查看器作用域与 Blob 缓存，并丢弃旧请求结果。 |
| 人物相册中的照片可能不在首页，点击时仍从首页照片池定位 | 人物接口返回经过脱敏、经过权限过滤的完整查看器数据，查看器使用当前人物照片作用域。 |

手工相册列表、详情、照片所属相册摘要也不再返回被权限过滤掉的封面照片标识，回落到当前可见的照片。

API 方法白名单同时收紧了两步验证和照片表态的允许方法，保留默认管理员策略。HEAD 和尾部斜杠采用与读取路由一致的判断。

## 统一的访问规则

1. 身份级别与密码是独立条件。输入正确密码不能让访客查看“仅登录”或“仅管理员”相册。
2. 一张照片属于多个手工相册或人物时，访问级别取最严格条件；不能通过另一本公开相册绕过限制。
3. 扫描文件夹访问级别继承整条目录链最严格的设置；密码继承最近设置密码的目录。子目录独立设置密码后，父目录解锁不能穿过该边界。
4. 只解锁某个子目录，不等于解锁父目录或兄弟目录。同样的中文字符数量、下划线形式或密码文本不能使不同作用域混淆。
5. 首页展示开关与读取权限分别处理。相册内可见且不进首页的照片，使用相册自己的查看器作用域。
6. 管理 API 只允许数据库中 role=admin 的账号。管理员仍具有管理资源的能力；“管理员免输相册密码”设置控制前台相册的锁定体验，不撤销管理员的管理权限。
7. 原图、缩略图、代理缩略图、人脸裁剪、地图缩略图、LivePhoto 信息、嵌入视频与 BGM 都在输出内容之前校验访问权。

## 自动验证

使用 Node 24：

```sh
pnpm test:permissions
```

该命令运行权限单元测试和生产处理函数的 HTTP 回归，不会启动 Nuxt、构建镜像或连接现有数据库。测试会创建内存 SQLite 和临时照片目录，并在结束时清理。SQL 使用项目真实 schema、真实 Drizzle 同步 session、真实权限函数及真实 HTTP 处理函数；通过 node:sqlite 适配器避免宿主机与 Alpine 的 better-sqlite3 二进制差异。外部 OAuth 提供方、设置来源、存储配置和 ML 输入边界使用测试夹具；目录生效权限、密码元数据与照片权限查询使用真实服务代码。

覆盖范围包括：

- ASCII、中文、空格、百分号、字面量 `%20`、emoji、连续点号文件名的“列表可见 → 打开原图/缩略图”正向访问。
- 访客、普通账号、管理员对画廊、地图和媒体出口的一致结果。
- 多相册最严格权限、人物限制、人脸裁剪、LivePhoto 视频、密码边界、兄弟目录和指定账号免密。
- 密码变更使旧令牌失效、条件请求重新鉴权、删除账号和角色降级。
- 嵌套扫描树、封面、计数、音乐的脱敏，以及未完成安装向导关闭后的拒绝行为。
- OAuth 两步验证、挑战重放、普通密码登录、普通账号自身会话、前端后台守卫。
- 退出账号后 Blob 缓存失效，旧下载或预取结果不回写缓存。
- 人物照片选择器 105 条候选的稳定分页及管理权限。

提交前还执行项目源码 lint、远程 vue-tsc --noEmit 和 git diff --check。具体结果以本轮任务最后的执行记录为准。

## 部署后的行为与验证边界

- 新的非根扫描目录 Cookie 名与旧版不同；此前在子目录输入过密码的浏览器，更新后需要重新输入一次。无需清空或重建数据库。
- 缓存重新鉴权可以限制后续请求；已经显示或下载的图片不能从访问者设备上收回。
- 本轮没有运行镜像或真实浏览器测试，也没有联系真实 OAuth 提供方。重新构建部署后，应使用访客、普通账号和管理员分别检查首页、相册刷新、人物照片、地图弹窗，以及密码父目录/独立密码子目录。
- 本地扫描库和本地上传可通过本应用媒体出口执行权限。若另行启用对外公开的 S3/CDN/OpenList 原始地址，外部公开链接的权限仍由外部存储决定；不能把本应用的相册密码当作外部公共文件的访问控制。

本轮未执行 git add、git commit 或 git push。提交时应包含新增权限辅助模块、会话插件、回归测试及其夹具，避免只提交已跟踪文件。
