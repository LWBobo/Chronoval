## 1. 数据库与部署前提

本实现面向全新数据库，直接更新 `server/database/schema.ts`、`migrations/0000_baseline.sql`、`meta/0000_snapshot.json`，没有编写旧数据迁移。新增结构包含账号状态、会话版本、照片归属、共享关系、文件登记、上传会话、配额预留、物理转移清单和审计。

现有旧数据库不能直接用于新代码。后续部署应由管理员自行准备全新数据库并完成初始化；本次没有执行任何删库操作。重新扫描 NAS 目录只建立站点图库索引，不搬动或删除原目录。重建数据库也不会替旧上传文件自动恢复个人所有权和授权关系。

基线含 35 张领域表、FTS5 OCR 虚表及 15 个跨表约束/版本触发器。用户名不可修改；人脸与人物、人物与集合必须处于同一所有者分区；嵌入视频必须引用同照片原件且字节范围合法。

`scripts/generate-baseline.mjs` 只用于明确需要重建空库基线时生成 SQL 和快照，不打开应用数据库。不要把它当作旧库升级命令。

## 3. 用户和页面行为

账号只由管理员创建，不开放注册。用户名在服务端规范化为小写、全站不重复、创建后固定；停用或注销也不回收用户名。昵称可修改。创建成功只在当次响应返回初始密码；普通账号首次登录必须改密。

管理员可设置角色、上传开关、配额，禁用/恢复、撤销会话、重置密码/TOTP，并选择“转移照片”或“删除照片”注销账号。最后一个有效管理员不能被禁用、删除或降级。禁用、改角色、改密等通过 `authVersion` 使旧会话失效。

个人空间包含“我的照片、我分享的、分享给我的、回收站、账号安全”。照片范围为 private/public/shared；shared 接收者只有读取和下载权，没有改名、删除、再次共享或所有权。管理员可以管理全部照片，前台画廊与管理查询采用不同上下文，防止管理员登录后把他人私密照片混入首页。

管理页面新增用户管理、全站照片和审计入口。用户详情展示空间账本、照片统计、活动转移和最近管理记录；可按所有者跳转照片列表。照片列表支持可见性、处理状态、上传日期筛选，管理端还支持来源、所有者、上传者及屏蔽状态。批量权限和回收站操作先验证整批权限及版本，任意冲突整批回滚。

普通用户的共享对象搜索至少输入 3 个字符，匹配用户名此前缀或完整邮箱，最多返回 20 条搜索结果，不返回邮箱。已存在共享的接收者可以按 ID 回显；不能用任意 ID 列表查询全站账号。管理员的管理选择器可以查找已停用账号；真正保存权限时仍拒绝无效接收者。搜索设账户/IP 请求预算。

## 4. 原件、派生文件和资源 URL

默认个人目录结构如下；若存储已配置其他 prefix，以绑定 provider 的 prefix 为准。

```text
photos/
  alice/
    旅行/IMG_0001.HEIC
    旅行/IMG_0001.MOV
    _duplicates/{photoId}/旅行/IMG_0001.HEIC
    .chronoval/{photoId}/preview.jpeg
    .chronoval/{photoId}/thumbnail.webp
```

合法原文件名、目录层级及字节保持不变。同用户发生路径冲突时，整组进入 `_duplicates/{photoId}/{原路径}`，不覆盖已有文件；不同用户目录相互独立。HEIC/RAW 转换、预览、缩略图和位置隐私处理只写派生副本。管理员站点上传使用 `photos/.site/{photoId}/`，普通用户不能写扫描库。

文件定位只从 `photo_files` 读取。公开请求为 `/api/assets/{32位随机十六进制ID}`；视频和动态视频的路径及查询参数无需包含原文件名、video、.mp4、.mov。原图、预览、缩略图、独立视频和嵌入视频均在读取时检查同一照片权限，支持 HEAD 和单段 Range，响应 `private, no-store`。

旧路径仅在能够对应到已登记文件并通过授权时服务，不提供任意存储键、外部 URL 或未登记文件的读取回退。已删除旧的响应重写插件及可逆 asset 编码工具，避免把随机文件 ID 再改写成失效旧 URL。

上传及后续读取、转移、清理绑定具体 provider ID，不跟随默认存储切换。受控上传实现 local 和 S3 条件创建；OpenList 受控上传明确返回不支持，不退回覆盖写入。S3 的真实服务往返尚未实测。

## 5. 上传、空间和任务恢复

上传按“初始化并预留→接收并校验部件→独占写入最终位置→事务登记/计费/入队→生成派生文件→ready”执行。照片在 ready 前不能对其他用户或公众发布。完成请求、重复 PUT、取消、过期和清理使用幂等键、状态和租约控制。

新账号默认配额 20 GiB，可设不限额；原件和独立实况视频计费，派生副本不占用户逻辑配额；回收站继续计费，彻底清理完成后才释放 used。local 的上传和转移会检查磁盘可用空间，实际写入失败仍依靠任务状态恢复，不能用逻辑配额代替磁盘容量。

单文件受站点 `system:upload.maxFileSize` 限制，并设 256 MiB 硬上限；图片另有 100 MiB 处理上限。界面展示单文件上限、待传总量和个人剩余配额。上传会话有效期 1 小时，界面最多并行 3 项；后台图片处理保留有界并发。

刷新页面可从服务器恢复当前账号、当前上传目标的未结束任务状态。浏览器不会持久化原文件字节；刷新前尚未完成传输的任务可以取消并重新选择原文件上传，不宣称支持跨刷新断点续传。已提交的 processing/failed 任务恢复后可继续查看进度或重试处理。

管理员用户详情可检查账本与文件登记是否一致。对账从计费原件登记、尚未释放的上传预留及转移目标预留重新求和，在事务内校验用户版本后修正，并记录原因与前后值；不会删除文件或减少实际配额要求。

## 6. 所有权转移、回收站及注销

个人照片转移由管理员发起，必须指定目标有效用户、当前 ACL 版本、幂等键及原因。扫描库照片保留 site 归属，不通过此操作把 NAS 目录变成个人上传目录。

转移持久化全部组件清单、源/目标位置、校验值及 worker 租约。源照片在 moving 时冻结；独立文件搬到目标用户名目录，嵌入视频随父原件搬运，文件 ID 保持不变。存在冲突时使用目标用户的独立冲突目录。

全部目标文件通过大小和 SHA-256 校验后，事务内切换 owner、配额和文件定位，强制 private、清空旧共享、删除旧所有者人物关联。原上传者字段保留用于审计，不授予持续访问权。普通旧所有者和旧接收者下一请求即失去权限；新所有者可查看和管理。

切换前失败只清理本任务目标副本并恢复原归属及配额；切换后源删除失败保留新归属和 cleanup_pending，不退回旧用户。此时新用户可读及改标题/说明/标签，暂不能改共享、改文件、再次转移或 purge。管理员可查看组件及字节进度、错误并重试清理。全部源文件清理后才标 completed。

普通用户回收站只显示本人照片，彻底删除须先入回收站；扫描库删除仅清索引和内部副本，保留 NAS 原文件。账号注销先阻断访问，再等待所有上传残留、照片及活动转移处理完毕，最后清授权和个人资料、保留不可复用的用户名记录。

当前运行模型为单个应用 Node 进程和 SQLite。purge/上传清理的进程内互斥防止同进程多个 worker 重复执行外部清理；持久状态用于重启恢复。本次没有扩展成多应用实例共享文件系统的清理锁架构。

## 7. 三类相册统一覆盖表

| 行为 | 自建相册 manual | 映射/目录相册 folder | 站点人物相册 person |
| --- | --- | --- | --- |
| public/login/selected/admin | 统一策略 | 统一策略 | 统一策略 |
| 指定可见用户名单 | `collection_viewers` | 同左 | 同左 |
| 密码、独立免密范围及名单 | 统一服务 | 同左，最近显式密码边界 | 同左 |
| 公共权限组件与预览 | `CollectionAccessEditor` | 同左，含根及子目录 | 同左，列表及详情 |
| 版本、批量更新、原因及审计 | 统一接口 | 同左 | 同左 |
| 父目录范围交集 | 不适用 | 逐级生效 | 不适用 |
| 与照片自身及其他集合权限交集 | 生效 | 生效 | 生效 |
| 重扫或展示资料修改保留权限 | 生效 | 生效 | 生效 |

可见名单和密码免密名单分表，免密不授予进入资格。照片同时处于多个站点相册时取交集；换相册地址、解锁密码或直接取媒体都不能扩大照片权限。预览在回滚事务中模拟，包含其他集合的阻断统计，不写真实 ACL、版本或审计；前端忽略条件变化前的迟到结果。

个人自动人物集合固定 owner/admin，只用于本人管理和人物分区，不会反过来阻挡已经共享的照片；接收者不能借共享照片看到私有人物姓名或人脸缩略图。人物合并限同一归属分区且权限、名单及密码策略完全一致；策略不一致时拒绝，需先明确统一，避免静默放宽。
